# rerank-latency sentences breaches the frame budget the benchmark checks: p95
# with the model is 20.64ms against 16.00ms, 129 of 1320 keystrokes (9.8%) cost
# more than one frame, and the slowest is 40.76ms. Measured on the locked
# resource set, 60 sentence cases, paired arms. A second run on the same
# machine gave p95 19.29ms and 8.9%, so read these as the scale of the
# overshoot rather than an exact figure - which is also why the gate records
# a name here instead of a committed millisecond threshold.
#
# This is pre-existing debt, not a regression. The benchmark landed in 418b4fb78
# and nothing ever invoked it, so a budget that fails has been failing unseen
# ever since; wiring it into this script without recording the current state
# would turn the whole run red on a cost this change did not create.
#
# The overshoot is not spread evenly. Reranking cost grows with the length of
# the sentence being scored, so it concentrates in the longest inputs - s-053
# 40.8ms, s-052 34.7ms, s-051 31.5ms - which are also where the model's own
# accuracy is weakest. The median keystroke pays 0.36ms, because most keystrokes
# never reach the model at all.
#
# Delete this line when p95 comes back under budget.
rerank-latency sentences

# windows-session-smoke stops at "Active candidate translation was not
# re-dispatched", which is an input the suite documents rather than a defect:
# it takes an optional absolute resource directory as argv[1], and without one
# its dictionaries are empty temp directories, so typing "ni" produces no
# candidate to translate. The outer "Preference retry task failed" used to hide
# this - a require() inside a queued task throws on the worker thread and the
# queue turns it into a status - which the harness now prints.
#
# Staging the artefacts from resources/desktop-dictionary.lock.json and passing
# them through MSIME_WINE_RESOURCES does not finish it either: preparation then
# fails under Wine at "Locked dictionary preparation failed", while the same
# msime_client_prepare_host call against the same directory returns ok:true
# natively. So that last step is a Wine limit, not a product one.
#
# Two earlier entries here were wrong about the cause and are worth remembering:
# session_pump.cpp:334 looked like punctuation routing and was ServerSession::key
# swallowing every unmodified letter (#3116, a real defect); the mode-notification
# loop looked like a product bug and was a wrong expectation about full/half-width
# (#3117).
wine windows-session-smoke
